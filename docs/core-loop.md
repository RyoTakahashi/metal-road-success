# コアループ詳細設計：意思決定 → 4KPI モデル (v0.1)

本書は `design.md §2` の具体化。**プレイヤーの意思決定 × バンドの状態** から
**動員数・ファン数・ストリーミング再生数・観客満足度** を算出するモデルを定義する。

> 数値・係数はすべて **暫定（チューニング対象）**。`【K】` を付した定数はバランス調整で動かす想定。

---

## 1. 設計思想

- ライブは「勝ち負け」ではなく **意思決定の答え合わせ**。
- 中核は **マッチ度**：「プレイヤーが狙った層・規模・楽曲」と「バンドの現状（能力・ファン層・知名度）」がどれだけ噛み合うか。
- **背伸び ⇄ 手堅さ** のトレードオフを常に効かせる：
  - 背伸び（大箱・格上フェス）＝ 当たれば新規リーチ大、外せば空席・赤字・満足度低下。
  - 手堅さ（小箱・既存層狙い）＝ ソールドアウトで満足度＆黒字は堅いが、成長は鈍い。

---

## 2. 状態変数

### 2.1 バンド能力（メインメンバーから集約）
メイン4パラメータ（体力を除く）をバンド単位に集約する。

| 記号 | パラメータ | 集約方法（v0.1） |
|---|---|---|
| `T` | 演奏基礎スキル | メインメンバーの平均（0–100） |
| `P` | パフォーマンス力 | 同上 |
| `S` | 音楽センス | 同上 |
| `V` | ビジュ力 | 同上 |

> v0.1は単純平均。将来はパート別重み（例：VoのV/P比重を上げる）を導入。

### 2.2 コンディション（体力 → 倍率）
栄冠の練習効率に倣い、体力で出力を割り引く。

```
Condition = 0.82 + 0.18 * (平均体力 / 100)      // 体力100→1.0, 体力0→0.82
```

### 2.3 ファン状態
- `TotalFans` … 総ファン数
- `SegFans[s]` … セグメント別ファン数（§3）
- `Fame` … 知名度（0–100）

### 2.4 裏方の効果（役割 → 補正係数）
裏方は `専門性` を主軸に、各役割の係数を生む（`人脈/コミュ力` は交渉・オファー質、`体力` は稼働持続）。

| 役割 | 主効果 | 影響先 |
|---|---|---|
| プロデューサー | 楽曲完成度 `Q` ↑ | 楽曲作成 |
| PA | 音響による満足度 ↑ | 満足度 |
| ローディー | 機材トラブル率 ↓ / 体力消費軽減 | 満足度・体力 |
| マーケティング担当 | 広告到達 `Mk` ↑ / タイアップ獲得力 | 動員・タイアップ |
| SNS担当 | バズ `Sn` ↑ | ストリーミング・新規リーチ |

各係数の基本形：`効果 = base + 専門性/100 * 【K_role】`

## 3. ファン層セグメント（MVPは4種）

各セグメントは「重視パラメータの重み」を持つ（行の和＝1.0）。

| セグメント | `T` | `P` | `S` | `V` | 性格 |
|---|---|---|---|---|---|
| コア（ガチメタラー） | 0.35 | 0.20 | 0.45 | 0.00 | 演奏・楽曲の質に厳しい |
| ライト（キャッチー/ノリ） | 0.10 | 0.40 | 0.20 | 0.30 | ライブの熱量・分かりやすさ |
| ビジュ（ルックス/カリスマ） | 0.05 | 0.35 | 0.10 | 0.50 | 見た目・スター性 |
| 玄人（音楽マニア） | 0.45 | 0.05 | 0.50 | 0.00 | 技術・独創性を評価 |

**セグメント別アピール値**（バンドがその層にどれだけ刺さるか）:

```
Appeal[s] = ( w[s].T*T + w[s].P*P + w[s].S*S + w[s].V*V )      // 0–100
Appeal_adj[s] = Appeal[s] * Condition
```

---

## 4. 楽曲（Song）

楽曲は「狙った層への寄せ `lean[s]`（和1.0）」と「完成度 `Q`（0–100）」を持つ。

```
Q = clamp( 0.6*S_band + 0.4*(Producer専門性) + 乱数±【K_q】 )
SongFit(t) = lean[t]            // ターゲット層 t への寄せ（0–1）
SongMatch(t) = SongFit(t) * (Q / 100)        // 0–1
```

---

## 5. 1ライブ／意思決定の解決フロー

プレイヤーが選ぶ意思決定パッケージ：**会場キャパ `Cap`**・**ターゲット層 `t`**・**セットリスト（楽曲）**・**（任意）フェス参加 / タイアップ**。

### Step 1. 露出係数
```
Exposure = 1 + Mk + Sn                       // マーケ・SNSの到達ブースト（≥1）
Tieup    = タイアップ有なら 1+【K_tie】, 無なら 1.0
```

### Step 2. 見込み動員 → 実動員
```
ExpDraw = SegFans[t] * 0.6 * (Appeal_adj[t] / 50) * Exposure
        + TotalFans * 0.05                    // 知名度による一般客の流入
Draw    = min( round(ExpDraw * 乱数(0.9–1.1)), Cap )
空席率   = 1 - Draw / Cap
```

### Step 3. 会場の熱気
```
Atmosphere = 100 * (Draw / Cap)               // ソールドアウトで100
if ソールドアウト: Atmosphere = min(100, Atmosphere + 【K_sellout=10】)
```

### Step 4. 観客満足度（KPI①）
```
Satisfaction = clamp(
      0.55 * Appeal_adj[t]
    + 0.30 * SongMatch(t) * 100
    + 0.15 * Atmosphere
    + PA補正 - 機材トラブル補正
)                                             // 0–100
```

### Step 5. 新規ファン獲得（KPI② への加算）
```
convRate = 0.15 * (Satisfaction/100)^1.5 * (1 + Sn)
ΔFans    = round( Draw * convRate )
SegFans[t] += ΔFans ;  TotalFans += ΔFans
```
> 満足度が低いと既存ファンが離脱（`ΔFans` が負方向の補正）も将来導入。

### Step 6. ストリーミング再生数（KPI③）
```
Streams = TotalFans * 3 * (Q/50) * Tieup * (1+Sn) * (Satisfaction/60)
```

### Step 7. 収支（資金）
```
Revenue = Draw*【チケット単価】 + Streams*【再生単価】 + タイアップ料
Cost    = VenueCost(Cap) + 制作費 + 人件費
利益     = Revenue - Cost                      // VenueCostはCapに比例（背伸びの痛み）
```

---

## 6. 4KPIまとめ

| KPI | 主ドライバ | 効く意思決定 |
|---|---|---|
| ① 観客満足度 | Appeal_adj[t]・SongMatch・空席率・PA | ターゲット層／楽曲／会場キャパ |
| ② ファン数 | 動員 × 満足度^1.5 × SNS | 会場規模／フェス／SNS投資 |
| ③ ストリーミング | 楽曲Q × 総ファン × タイアップ × SNS | 楽曲作成／タイアップ／SNS |
| ④ 動員数 | 該当層ファン × アピール × 露出（Cap上限） | 会場キャパ／マーケ／ターゲット層 |

---

## 7. 各意思決定の役割（プレイヤーが何を動かすか）

- **会場キャパ**：背伸び/手堅のメイン操作。空席リスク vs リーチ。
- **ターゲット層**：`Appeal_adj[t]` と `SongMatch(t)` の分母を決める。バンドの強みと一致させるほど満足度↑。
- **楽曲作成**：`Q` と `lean[s]`。狙う層と曲調を一致させる長期投資。
- **フェス参加**：大規模×他層リーチ。`Exposure` と新規 `SegFans` 開拓に強いが、格上フェスは空席相当（演奏順・印象）の罰則あり。
- **タイアップ**：`Streams` と `Fame` を底上げ。`人脈`（マーケ/マネージャー）で良案件を引く。

## 8. 数値例（ワークスルー）

バンド: `T60 P55 S50 V45`、平均体力80 → `Condition=0.964`
楽曲: コア狙い `lean.core=0.9`, `Q=70` → `SongMatch(core)=0.63`
裏方: `Mk=0.3, Sn=0.2` → `Exposure=1.5`
コア層ファン `SegFans.core=800`、`TotalFans=2000`

`Appeal.core = .35*60+.20*55+.45*50 = 54.5` → `Appeal_adj=52.5`
`ExpDraw = 800*0.6*(52.5/50)*1.5 + 2000*0.05 = 756 + 100 = 856`

| 判断 | Cap=500（手堅） | Cap=1000（背伸び） |
|---|---|---|
| 実動員 Draw | 500（ソールドアウト） | 856 |
| 空席率 | 0% | 14.4% |
| Atmosphere | 100 | 85.6 |
| 満足度 | **≈64** | **≈60** |
| 新規ファン ΔFans | ≈46 | ≈73 |
| 収支リスク | 低（黒字堅い） | 高（会場費2倍） |

→ 小箱は満足度・採算が堅実、大箱は新規リーチ大だが満足度減＆赤字リスク。**狙い通りトレードオフが成立**。

## 9. 未確定・調整項目

- 定数 `【K_*】`／単価のバランス調整
- 既存ファンの**離脱**モデル（満足度低下時）
- セグメント間の**波及**（コアで売れると玄人にも染み出す 等）
- フェスの罰則（演奏順・対バン格差）の式
- 「炎上」などマイナスイベントのKPIへの織り込み
