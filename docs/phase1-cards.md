# Phase 1 設計メモ：選択カード制＋パート選択＋資金ゲート＋継続要求（提案 v0.1）

対象：ロードマップ C1 / C2 / D2 / D3。既存の `state.ts`・`coreLoop.ts`・`narrative.ts`・
`render.ts`・`main.ts` にどう載せるかの具体案。**数値は暫定**。

---

## 0. コンセプト
- プレイヤー＝**バンドのリーダー（意思決定者）**。
- 1ヶ月 = **数ターンの行動**（例：4ターン）＋**月末ライブ**。
- 各ターン、**行動カードの手札**が提示され、1枚選ぶ。手札は「常時カード＋半ランダムの発生カード」。
- 「完全ランダムのすごろく」から「**半ランダムで提示される選択**」へ。

## 1. ターン進行（現行すごろくの置き換え）
```
月開始 → [行動ターン ×N] → 月末ライブ → 決算 → 翌月
             └ 各ターン：手札ドロー → カード選択 → 解決（サブ選択あり）
```
- **N（月あたり行動数）**＝暫定 4。
- **手札の作り方**：
  - 常時：**①休息**（サブ：完全休養／社会勉強／趣味）
  - 半ランダム：**②音楽活動**（作曲／練習／パフォーマンス）**③広報活動 ④関係性構築**
    （バンド関係者／新たな人脈）**⑤アルバイト** から、毎ターン2〜3枚を抽選提示。
  - → 「常に休息はできる」「他は引き次第」。引きの巡り合わせを読むゲーム性。
- **サイコロの扱い（要決定・§7）**：出目×効果は廃止し、効果のブレは「カードのレア度＋小さな乱数」に寄せる案を推奨。

## 2. 型・状態の変更（types.ts / GameState）
新規：
```ts
type ActionKind = "rest" | "music" | "promo" | "network" | "money";
type RestSub    = "full" | "study" | "hobby";
type MusicSub   = "compose" | "practice" | "perform";

interface ActionCard {
  kind: ActionKind;
  label: string;
  always: boolean;        // 常時提示（休息=true）
  subs?: string[];        // サブ選択（音楽活動/休息など）
}
```
`GameState` 変更：
- 追加：`turn: number`（月内ターン, 1..N）、`turnsPerMonth: number`、`hand: ActionCard[]`。
- 追加（D3 継続要求）：各 `Song` に `age: number`（リリースからの経過月）、
  バンドに `practiceFreshness: number`（0–100, 練習の鮮度／サボると減衰）。
- 追加（C1）：`leaderPart: string`（プレイヤーのパート）、`members[i].isLeader`。
- **廃止/縮小**：`board/pos/Space/SpaceKind`（すごろくを撤去、または月表示用の簡易タイムラインに縮小）。

## 3. C1 パート選択（プレイヤー＝リーダー）
- タイトル→開始時に **Vo/Gt/Ba/Dr から自分のパートを選択**。
- 選んだパートの既存メンバー（RYO/KEN/MIO/GO）が **あなた＝リーダー**。
  - リーダーのパラメータに小さな初期ボーナス、一部イベントの主役が変化。
- （要決定・§7）カスタム名も付けられるようにするか。

## 4. D2 資金ゲート（序盤の導入）
- ライブ開催に**会場費の前払い**を要求（`VenueCost(cap)` を事前に支払えないと、その規模は選べない）。
- 序盤は資金が乏しく、**⑤アルバイト**で開催費を貯める必要がある。
- 実装：`resolveLive` 前の意思決定画面で、`funds >= venueCost(cap)` を満たすキャパのみ選択可能に。

## 5. D3 継続要求（新曲＆練習の必要性）
- **新曲**：`Song.age` が増えるほどストリーミング/新規獲得の伸びが鈍化（陳腐化）。
  数ヶ月ごとに②音楽活動＞作曲で新曲を出さないと知名度/ファンが伸びない。
- **練習鮮度** `practiceFreshness`：毎月自然減衰。低いとライブの実効パラメータに**マイナス補正**が
  かかり、広報の如何に関わらず満足度・新規獲得が落ちる（＝ファンが増えない/減る）。
- `coreLoop.ts` の `appealAdj` / `resolveLive` に鮮度・曲age補正を追加（`【K】`化）。

## 6. UI（render.ts / main.ts）
- ボード描画を**手札カードUI**に置換：手札を横並びカードで表示、選択でサブ選択モーダル→紙芝居→反映。
- タイトルに**パート選択**ステップを追加。
- ライブ意思決定画面に**資金でロックされたキャパ**表示。
- メイン画面の hero（バンドの様子）・ログ・topbar は流用。
- `narrative.ts` は各行動カードの紙芝居（②〜⑤）を追加。既存の練習シーンは②音楽活動＞練習に流用。

## 7. 確定事項（2026-07 レビューで決定）
1. **すごろく撤去 → 毎ターン手札制**。board/pos/Space を廃止。
2. **サイコロ×出目は廃止**。効果ブレはカードの種類＋小さな乱数へ。
3. **パート選択＋カスタム名**。選んだパートの既存キャラがリーダー＝あなた。
   スプライトは `artKey`（ryo/ken/mio/go）で引き、表示名だけ差し替え可能に。
4. **月あたり行動ターン数 N = 4**（暫定）。初期資金/バイト額/会場費は推奨スケールで実装しプレイ調整。

> 実装順：`types.ts`→`state.ts`→`coreLoop.ts`→`narrative.ts`→`render.ts`/`main.ts`。
> ①休息＋②音楽活動（既存練習を吸収）＋⑤バイトを先に通し、③広報・④関係性を足す。
